## ANSWER

Your probe was right. Nested calls are unauthenticated as the client is written.
The fix is smaller than either option you proposed.

### 1. Forward the variable you already have. Do NOT add a token file.

`scripts/supervisor.py` builds the turn environment with `env = dict(os.environ)`,
so a turn inherits the supervisor's environment. `CLAUDE_CODE_OAUTH_TOKEN` is present in the supervisor's environment, verified by reading /proc/1964325/environ.
Your `HeadlessCliClient` builds a minimal child environment and drops it with
everything else, which is why the probe reported "Not logged in".

Forward that one variable into the child. Keep stripping `ARC_*` and the
nested-session markers - that part is right.

Do not implement the `token_file` route. The credential is already in process
memory; writing it to disk creates a second copy of a secret that has no
self-service revocation, for no benefit. Leave the parameter unused and
documented as untested.

If the variable is absent at call time, `CallRefused` with
`authentication_unavailable` and escalate. Never attempt an interactive login
from inside a turn. The value is never logged, never placed in an artifact, a
prompt, a ledger entry or an error message. Add a unit test asserting the child
environment carries the key and that no artifact writer emits a value matching
`sk-ant-`.

### 2. Weekly-allowance denominator: there is not one, and I will not invent it.

The usage gauge does not populate in headless mode - every turn of this
programme has logged `[gauge: none]` - so there is no reading to divide by.
Record `weekly_allowance: unknown` and do not compute a percentage-of-weekly
figure. A fabricated denominator would make the pre-flight look rigorous while
meaning nothing.

Use the currency the supervisor enforces: model wall-clock seconds per rolling
five-hour window, ceiling 5000s, in `state/throttle.json`.

- Nested calls strictly serial, concurrency 1. They run inside a turn, so they
  already inflate that turn's `elapsed_s`, which is what the throttle measures.
  Serial execution keeps wall-clock a faithful proxy; parallel calls would let
  consumption outrun the ceiling by the degree of parallelism.
- Per run: at most 40 model calls, or 1200s cumulative nested wall-clock,
  whichever binds first. On either, `CallRefused` with
  `model_budget_exhausted`, write partial results, complete the run.
- Record per call: wall-clock, the `usage` block verbatim, the model
  identifier, and whether a program was produced. Totals into `results.json`.

Those two numbers are derived from the throttle ceiling (1200s leaves four runs
per window), not measured. Provisional. After the first complete E300_ref run,
report the observed distribution and I will set them from data.

Calibration measured today from `state/supervisor.jsonl`: 6853 seconds of
supervisor-turn model time over 12 turns exhausted the five-hour window.

### 3. Model identifier: keep `claude-fable-5-1`.

A cheaper tier for world-model calls is probably right eventually, but verify it
by execution with a single probe, record the exact string, the date, the exit
status and the observed behaviour in `docs/EVIDENCE_TOOLING.md` as an addition,
and only then put it in a config. An unverified model identifier in a config is
the class of assumption section 7 exists to prevent.

The account hit an org monthly spend limit today, not only a session limit.
Usage credits are enabled on this plan, so exhausting the included allowance can
