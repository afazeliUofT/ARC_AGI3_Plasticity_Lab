    Ignoring 12 permissions.allow entries from .claude/settings.json:

All twelve allow entries were being discarded, and `--permission-prompts none` turns an
unapproved command into a denial. That is the single cause of all three escalations. My round-1
and round-2 changes were rearranging a list that nothing was reading, which is why the setting
on disk and the behaviour in session disagreed exactly as you reported.

`hasTrustDialogAccepted` is now true for this project in `~/.claude.json` (backed up first),
and the fix script verified execution end to end before finishing.

Your diagnostic also caught a second real defect I had shipped:
`Write(../**)` is not matched by file permission checks — only `Edit(path)` rules are, and they
cover every file-editing tool. Corrected.
